작성: 2026-05-14 (office-hours 세션 5) 근거: Document/design-20260513-104744.html (디자인 v3 액션 1) + samples/sample.json 발견 후 v3 v0.1 컨벤션 갱신 + Document/design-actor-selection-20260515-140853.html (actor 선택 표준 락) 상태: v0.1.1 (2026-05-15 actor 선택 표준 추가, 솔로 실행 모드로 합의 회의 폐기) mode: Solo execution

이 문서의 역할

Unreal export 코드와 웹 로더가 둘 다 참조하는 단일 계약서. 디자인 v3의 1주차 액션 1 산출물.

v0.1 범위: 1주차 vertical slice 합격에 필요한 최소 계약 (Unreal에서 옮긴 모델 위치가 웹에 반영 + 1인칭 SPZ 공간 충돌 + 모델 클릭 콘솔 출력).

v0.2 이후 예정: anchor_type enum 확장 (start_pos, teleport, farming, elevator 등 풀 시스템 진입 시), collision_type enum 확장 (mesh), 트리 구조 wrap 가능성 (scenes[]).

설계 출발점은 samples/sample.json (회사 Caliverse 메타버스의 과거 콘텐츠 포맷, 현재 비운영) 컨벤션을 가볍게 흡수. 풀 시스템 진입 시 마이그레이션 부담을 줄이기 위해 필드 명칭·구조를 최대한 미래와 충돌하지 않게 잡음.

좌표계·단위 합의

항목 값 비고
coord_system "ue" Unreal: left-handed, Z-up, X-forward
unit "cm" NanoGS가 meters → cm 변환하므로 cm 기본
씬 전체 yaw 보정 space.rotation_y_deg 현재 검증값 -90 (Postshot → splat-transform → Spark chain 기준, 2026-05-13 G 키 사이클로 확정)
모델별 좌표·회전 변환 웹 로더 책임 Unreal → Three.js Y-up right-handed 변환 수식은 2주차 1일차 검증으로 확정 (Open Question 2 참조)

루트 객체

필드 타입 필수 설명
schema_version string O "0.1". 웹 로더가 호환성 확인에 사용
scene_id string O 씬 식별자. 파일명·캐싱 키
coord_system string enum O "ue" (v0.1은 "ue"만)
unit string enum O "cm" (v0.1은 "cm"만)
space object O SPZ 공간 정보 (아래 참조)
anchors array O 씬 안에 배치된 객체 목록 (아래 참조)

space 객체

필드 타입 필수 설명
spz_path string O Spark 적재용 SPZ v3 (gzip). splat-transform -H 1 --spz-version 3 출력
ply_path string △ NanoGS 적재용 원본 PLY (Postshot 출력 INRIA spec). Unreal 측만 사용
collision_path string O SPZ 공간 벽·바닥 invisible GLB mesh. Unreal Modeling Mode 작성
rotation_y_deg number O SPZ 측 yaw 보정 (도 단위). 현재 검증값 -90

경로는 scene00.json 파일 기준 상대 경로. UTF-8 without BOM.

anchors[] 객체

필드 타입 필수 설명
anchor_type string enum O v0.1은 "model"만. v0.2 이후 "start_pos", "teleport", "farming", "elevator" 등
id string O 씬 내 유일. 클릭 이벤트의 콘솔 출력 키
editor_name string O 사람이 읽는 표시명. 1주차엔 영문 키워드, 다국어는 v0.2
glb_path string O (anchor_type=model) 시각용 GLB. collision_type="bbox"이면 BBox는 GLB 자체에서 자동 계산
position object {X,Y,Z} O cm, Unreal 좌표계
rotation object {Pitch,Yaw,Roll} O 도 단위, Unreal Euler
scale number O scalar uniform scale (sample.json 컨벤션)
collision_type string enum O v0.1은 "bbox"만. v0.2 이후 "mesh"
extra object × forward-compat용. GUID·TableID·ClassName·MannequinItems 등 회사 메타 자유 첨부

명칭이 models 가 아니라 anchors인 이유: 풀 시스템 진입 시 start_pos/teleport/farming/elevator 같은 비-모델 객체가 들어올 자리를 미리 마련.

forward-compat 정책

웹 로더:

  • 정의되지 않은 root-level 필드 무시
  • 모르는 anchor_type (v0.1은 "model" 외) → console.warn 후 skip
  • 모르는 collision_type → fallback "bbox" + console.warn
  • schema_version 미일치 (예: "0.2") → console.warn 후 진행 시도

Unreal export:

  • v0.1에 정의되지 않은 필드 출력 허용 (extra.* 또는 root-level 자유)
  • schema_version 필드는 반드시 "0.1"로 출력
  • 좌표·회전·스케일은 Unreal 원본 값 그대로 (cm·도·scalar)

이 정책으로 1주차 v0.1과 풀 시스템 v0.2 사이에 양쪽 도구를 동시에 깨지 않고 점진 전환 가능.

회전·좌표 변환 (참고, 2주차 검증으로 확정)

웹 로더가 Unreal → Three.js로 변환하는 의사 코드. 검증값은 2주차 1일차 산출.

// 좌표: Unreal (X-forward, Y-right, Z-up, cm) → Three.js (X-right, Y-up, Z-back, m)
// 검증으로 부호·축 swap 확정 예정.
position_three.x = position_ue.X / 100;
position_three.y = position_ue.Z / 100;
position_three.z = -position_ue.Y / 100;

// 회전: Unreal Pitch/Yaw/Roll (도) → Three.js Euler (라디안)
// order 'YXZ' 가정. 검증으로 확정 예정.
const yaw   = THREE.MathUtils.degToRad(rot_ue.Yaw);
const pitch = THREE.MathUtils.degToRad(rot_ue.Pitch);
const roll  = THREE.MathUtils.degToRad(rot_ue.Roll);
obj.rotation.set(pitch, yaw, roll, 'YXZ');

// 씬 전체 SPZ yaw 보정 (이미 검증됨)
splat.rotation.y = THREE.MathUtils.degToRad(json.space.rotation_y_deg);

검증 절차: 2주차 1일차에 모델 1개를 Unreal 임의 위치·회전으로 배치 후 웹에서 일치 확인. 어긋남 발생 시 부호·축 swap 또는 Euler order를 G 키 사이클 식으로 토글해 시각 비교.

Open Questions

  1. Euler order 확정: Three.js 'YXZ' 가정. Unreal 회전 합성 순서가 Yaw → Pitch → Roll (UE 내부)이라 'YXZ'가 자연. 2주차 1일차 검증.
  2. 좌표 부호 swap 확정: z_three = -y_ue 가정. 검증 어긋남 시 토글.
  3. extra 객체 표준 키: 풀 시스템 진입 시 extra.guid, extra.table_id, extra.class_name 명문화 필요. v0.1은 자유.
  4. collision_type="bbox"의 BBox 계산 위치: GLB 적재 후 Three.js Box3.setFromObject() 사용 가정. Unreal export 시점에 미리 계산해 JSON에 넣을지 v0.2 결정.
  5. glb_path 누락 시 동작: anchor_type이 "model"인데 GLB 없으면 v0.1은 console.warn 후 skip. v0.2에서 sprite/anchor 타입 추가 시 정책 재검토.

actor 선택 표준 (v0.1.1, 2026-05-15)

Unreal Editor Python script가 EditorActorSubsystem.get_all_level_actors() 결과 중 anchors[]로 export할 actor를 결정하는 표준.

선택 메커니즘: BP 클래스 상속 (BP_Anchor_Base BP-only 슈퍼클래스 + 파생 BP들).

  • BP_Anchor_Base (Actor 파생, BP-only): instance editable 변수 Id/EditorName/Extra (Map<FString,FString>) 노출.
  • BP_Anchor_Model (Base 파생): 추가 변수 GlbPath/CollisionType (User Enumeration E_CollisionType BBox/Mesh).
  • v0.2 enum 확장 (teleport/start_pos/farming/elevator 등): BP_Anchor_X 파생 추가만으로 자동 포함, export 코드 변경 불필요.
  • C++ 슈퍼클래스 승격은 anchor_type 2개째 추가 시점(= 풀 시스템 진입). v0.1은 BP-only.

필터 코드 패턴:

def is_anchor(actor):
    cls = actor.get_class()
    while cls:
        if cls.get_name() == "BP_Anchor_Base_C":
            return True
        cls = cls.get_super_class()
    return False

anchor_type 결정: 파생 BP 클래스명 → 매핑. BP_Anchor_Model_C → "model", BP_Anchor_Teleport_C → "teleport" 등 lowercase 변환.

extra 직렬화: 비어 있어도 {} 항상 출력 (diff 안정성). schema는 옵셔널이지만 export script는 always-emit.

합의 회의 체크리스트 (폐기, 2026-05-15)

솔로 실행 모드 결정으로 별도 회의 폐기. 5건은 다음과 같이 self-결정으로 종결:

  • coord_system="ue" + unit="cm" — 검증값 그대로 채택.
  • space.rotation_y_deg=-90 — Postshot chain 검증값 그대로 채택.
  • anchor_type v0.1 = "model"만 — 사용자 P-Act2 동의로 확정.
  • collision_type v0.1 = "bbox"만 — 사용자 동의로 확정.
  • extra 객체 — v0.1은 항상 {} 출력 (always-emit). 회사 표준 키(GUID/TableID/ClassName) 명문화는 v0.2.
