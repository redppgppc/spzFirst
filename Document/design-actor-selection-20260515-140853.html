작성: 2026-05-15 (office-hours 세션 6) 모드: Startup (서브 결정 — 부모 디자인 v3 보강) 상태: APPROVED 부모: Document/design-20260513-104744.html (v3, 현행) 영향 문서: Document/json-schema-v0.1.html (actor 선택 표준 단락 추가, v0.1.1 패치)

이 문서의 역할

디자인 v3 액션 3 (Unreal NanoGS 배치 + collision proxy 작성 + JSON export 코드 + scene00 묶음 저장) 중 JSON export 코드의 첫 결정인 "레벨 안의 어떤 actor를 anchors[]로 export할 것인가" 선택 메커니즘을 잠그는 서브 디자인 문서.

todo.html 미해결 항목 "JSON export actor 선택 기준 결정" + json-schema-v0.1.html "합의 회의 체크리스트"의 잠재 항목을 닫는다. 이 결정으로 export Python script · scene00 폴더 구조 · v0.1.1 스키마 패치 세 곳이 동시에 잠긴다.

Problem Statement

Unreal 레벨에 NanoGS SPZ 공간 + collision mesh + 모델 BP들이 함께 놓인 상태에서, Python script가 EditorActorSubsystem.get_all_level_actors()를 호출했을 때 어떤 actor들만 골라 anchors[]로 export할지의 필터 기준을 정한다.

후보 4종:

  • A) 전체 StaticMeshActor (필터 없음)
  • B) Tag 기반 (anchor_model 같은 actor tag)
  • C) World Outliner 폴더 (Anchors/)
  • D) BP 클래스 상속 (BP_Anchor_Base superclass + 파생 BP들)

이 결정은 풀 시스템(myWorkTodo.html 12개 요구사항 통합)으로 확장 시점에 anchor_type enum (start_pos/teleport/farming/elevator 등) 분기 기반과 직결된다.

Approaches Considered

Approach A: Lean MVP — 슈퍼클래스 생략 (단일 BP)

  • Summary: BP_Anchor_Model 한 개만 만들고 Python에서 그 클래스 직접 체크. 슈퍼클래스 추가는 anchor_type 2종째 등장 시.
  • Effort: S (30분)
  • Risk: Low
  • Pros: 1주차 셋업 최소. anchor_type=model만 있는 1주차 자체엔 군더더기 없음. BP reparent로 후속 마이그레이션 거의 0.
  • Cons: P-Act1 정신 약화 (사용자의 ACVAnchor 패턴이 1주차에 시각적으로 안 보임). JSON export 코드를 곧 슈퍼클래스 traversal로 다시 손대야 함.
  • Reuses: EditorActorSubsystem.get_all_level_actors() + 단일 클래스 비교 한 줄.
  • Completeness: 6/10

Approach B: Pure BP — 슈퍼클래스 + 1종 파생 (★ 채택)

  • Summary: BP_Anchor_Base (Actor 파생) 슈퍼클래스 + BP_Anchor_Model (Base 파생). Details 패널에 id/editor_name/extra 노출. Python에서 슈퍼클래스 파생 actor만 traverse.
  • Effort: S (1시간)
  • Risk: Low
  • Pros: 1주차에 사용자 검증 패턴이 즉시 코드로. v0.2 anchor_type 확장 시 BP_Anchor_X 파생 추가만으로 끝. JSON export 코드 한 번 작성 후 재작성 불필요. samples/sample.json 트리 구조와 명확한 매핑.
  • Cons: 셋업 30분 더. wedge가 "필요 이상으로 큼"이라 느낄 수 있으나 재작성 회피로 총 비용은 A와 비슷.
  • Reuses: 사용자 이전 ACVAnchor 워크플로 그대로. samples/sample.json 패턴 일치.
  • Completeness: 9/10

Approach C: Pre-architected — placeholder BP들 미리 생성

  • Summary: B + 빈 placeholder BP들(BP_Anchor_Teleport, BP_Anchor_StartPos)을 1주차에 미리 만들고 Python export에서 anchor_type별 분기 자리도 pre-wired.
  • Effort: M (2~3시간)
  • Risk: Med (P-Act2 위반)
  • Pros: 풀 시스템 진입 매우 매끄러움. 사용자가 "여기에 teleport BP 끌어다 놓으면 됨"이 시각적으로 즉시 인지.
  • Cons: P-Act2 직접 위반 (1주차는 model 1종만). YAGNI. 1주차 합격 검증 면적 1종 → 다종 확대 = 디버깅 부담. 안 쓰는 BP가 git에 들어감.
  • Reuses: B 위에 placeholder 추가.
  • Completeness: 10/10 BUT 스코프 부풀림

Recommended Approach: B (Pure BP)

채택 근거:

  1. 사용자 도메인 경험 일치: ACVAnchor 슈퍼클래스 + 파생 BP + JSON export 패턴이 이미 검증된 워크플로. 동일 패턴 그대로.
  2. sample.json 동기화: 회사 과거 콘텐츠 포맷의 BP_Anchor_* 트리와 직접 매핑. 풀 시스템 진입 시 마이그레이션 부담 거의 0.
  3. v0.2 무마찰 확장: anchor_type enum (teleport/start_pos/farming/elevator 등)이 BP 파생 추가만으로 자연스럽게 확장. JSON export 코드 재작성 없음.
  4. 1주차 wedge 유지: anchor_type=model 1종만이라 P-Act2 부합. 셋업 1시간은 재작성 회피로 상쇄.
  5. 솔로 실행 적합: BP-only (P-Act3)라 C++ 컴파일 사이클 없음. Live Coding 안정성 리스크 회피.

A 비채택: 30분 절약은 후속 export 코드 재작성으로 상쇄. 사용자 패턴 정신을 1주차에 안 보여주는 손실 큼.

C 비채택: P-Act2 직접 위반. wedge 부풀림. anchor_type 2개째 등장 시점(= 풀 시스템 진입)에 B → C 확장은 자연스러움.

Python export script

D:\Temp\plyTest_5_7\Tools\export_scene_json.py (가칭):

import unreal
import json
import os

OUTPUT_DIR = r"D:\GitHub\Work\spzFirst\samples\scene00"  # TODO Open Question 5
SCHEMA_VERSION = "0.1"

def is_anchor(actor):
    cls = actor.get_class()
    while cls:
        if cls.get_name() == "BP_Anchor_Base_C":
            return True
        cls = cls.get_super_class()
    return False

def actor_to_anchor(actor):
    cls_name = actor.get_class().get_name()
    anchor_type = "model" if cls_name == "BP_Anchor_Model_C" else cls_name.lower()

    pos = actor.get_actor_location()
    rot = actor.get_actor_rotation()
    scale = actor.get_actor_scale3d()

    base = {
        "anchor_type": anchor_type,
        "id": actor.get_editor_property("Id"),
        "editor_name": actor.get_editor_property("EditorName"),
        # 좌표·회전·스케일은 cm·도·scalar Unreal 원본 그대로. 변환은 웹 책임 (P-Act4).
        "position": {"X": pos.x, "Y": pos.y, "Z": pos.z},
        "rotation": {"Pitch": rot.pitch, "Yaw": rot.yaw, "Roll": rot.roll},
        "scale": scale.x,  # uniform 가정. non-uniform이면 v0.2에서 객체화
        # extra는 비어도 {} 출력 (P-Act5 always-emit 정책)
        "extra": dict(actor.get_editor_property("Extra")),
    }

    if anchor_type == "model":
        base["glb_path"] = actor.get_editor_property("GlbPath")
        ct = actor.get_editor_property("CollisionType")
        # CollisionType은 unreal.EnumBase. 정수 비교는 int() 강제.
        ct_int = int(ct)
        base["collision_type"] = "bbox" if ct_int == 0 else "mesh"

    return base

eas = unreal.get_editor_subsystem(unreal.EditorActorSubsystem)
all_actors = eas.get_all_level_actors()
anchors = [actor_to_anchor(a) for a in all_actors if is_anchor(a)]

# id 중복·빈값 가드 (Open Question 6)
ids_seen = set()
for a in anchors:
    aid = a["id"]
    if not aid:
        unreal.log_warning(f"anchor with empty id: {a.get('editor_name', '?')}")
    elif aid in ids_seen:
        unreal.log_warning(f"duplicate anchor id: {aid}")
    ids_seen.add(aid)

scene = {
    "schema_version": SCHEMA_VERSION,
    "scene_id": "scene00",
    "coord_system": "ue",
    "unit": "cm",
    "space": {
        "spz_path": "scene00_v3.spz",
        "ply_path": "scene00.ply",
        "collision_path": "scene00_collision.glb",
        "rotation_y_deg": -90,
    },
    "anchors": anchors,
}

os.makedirs(OUTPUT_DIR, exist_ok=True)
out = os.path.join(OUTPUT_DIR, "scene00.json")
with open(out, "w", encoding="utf-8") as f:
    json.dump(scene, f, indent=2, ensure_ascii=False)

unreal.log(f"scene00.json exported: {out} (anchors={len(anchors)})")

UTF-8 without BOM. JSON output 파일은 git에 들어감.

Open Questions (이 결정 후 새로 부상)

  1. get_class().get_name()이 BP_Anchor_Base_C인지 BP_Anchor_Base인지 검증: Unreal Python API의 BP 클래스명 suffix 규칙 확인. 1차 export 실행 시 즉시 확인 가능. 동시에 4번 함께 결정.
  2. Extra Map 직렬화 순서: Python dict(unreal.Map) 변환 시 키 순서 보장 여부. 안정 정렬 필요하면 dict(sorted(...))로 변경.
  3. scale uniform 가정 위반 시: actor.get_actor_scale3d()의 X/Y/Z가 다르면 X만 채택하면 정보 손실. v0.1은 우선 첫 값만, 비균일 검출 시 console.warn. v0.2에서 scale: {X,Y,Z} 객체화 가능성.
  4. 클래스 비교 robust화: cls.get_name() == "BP_Anchor_Base_C" 문자열 비교는 BP rename·namespace 충돌에 취약. cls.get_path_name() 비교 (예: /Game/Anchors/BP_Anchor_Base.BP_Anchor_Base_C)가 더 안전. 1번과 같은 dry-run에서 get_path_name() 출력 확인 후 정책 확정. 1주차 단일 레벨에선 1번 비교로도 충분하나 풀 시스템 진입 전엔 path 비교로 승격 권장.
  5. scene00 출력 경로: 위 코드에선 samples/scene00/로 직접 출력하지만 1차 검증은 Unreal Content/Output 경로에 출력 후 수동 복사가 안전할 수도. 사용자 선호로 결정. 결정될 때까지 코드 상수에 # TODO Open Question 5 표기 유지.
  6. id 중복·빈값 정책: 현재 export script는 unreal.log_warning만 출력하고 진행. 1주차는 단일 anchor라 무관하지만 다중 anchor 단계 진입 전 hard fail (assert) 또는 자동 suffix 부여 정책 결정 필요.
  7. Multi-level 지원 시점: 현재 코드는 활성 레벨 단일. World Composition/World Partition 사용 시 traverse 변경 필요. 풀 시스템 진입 시 결정.
